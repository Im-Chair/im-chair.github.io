## 你的角色

協助開發「貪婪深淵」——繁體中文的瀏覽器 roguelite 地城遊戲。

- 純前端原生 HTML/CSS/JS,**無框架、無 build step**,直接開 `index.html` 就跑
- 不要引入 npm 依賴、打包工具或 ES module import
- 存檔在 localStorage(`abyss-acc-v1`),多角色槽 4 個 ＋ 共用倉庫

回報用繁體中文,簡潔,先講結論。動手前先說要改哪些檔案的哪幾處,改完列出所有觸及的位置。

## 檔案結構

載入順序固定寫在 `index.html` 底部:`data → core → account → items → battle → run → ui`

| 檔案 | 內容 |
|---|---|
| `data.js` | 純資料層:職業/技能/敵人/Boss/詞綴/藥水/域/事件常數 ＋ 平衡參數(`RATE_CAP`、`STAT_DIV`、`CURVE`、`DOT`、`CYC_MULT`)。**調平衡只改這裡** |
| `core.js` | 存檔、全域狀態 `G`(角色)/`R`(探索)/`B`(戰鬥)、屬性彙總、公用工具、`WALLET` |
| `account.js` | 帳號層:多角色槽、共用倉庫;`migrateChar()` 是存檔遷移的唯一入口 |
| `items.js` | 裝備生成/詞綴/裝備介面/鐵匠(精煉+重鑄)/深淵黑市 |
| `battle.js` | 敵人生成/回合流程/技能結算/狀態效果/戰利品 |
| `run.js` | 下潛選單/門/樓層推進/全部事件/商人/撤退與死亡 |
| `ui.js` | 標題/選職業/營地/角色檢視/圖鑑/存檔管理/啟動 |
| `_smoke.js` | Node 直接跑的無瀏覽器冒煙測試(`node _smoke.js`) |
| `_audit_assets.js` | 圖片資產對帳:遊戲會請求的圖 vs `sw.js` 登記 vs 硬碟實際檔案 |

圖片:`eq/`(裝備 16)、`mon/`(怪物 58)、`ui/`(介面 48),共 121 張 webp、約 3.0 MB。
`貪婪深淵-怪物素材/` 是 13 MB 原始素材,執行時不使用。

圖鑑目前 `CODEX_ENABLED=false`(改建中)。

> ✅ **工作目錄是網站根目錄 `im-chair.github.io/`(v432 起)**,所以 `rpg/` 與根目錄的
> `sw.js` 都改得到。以前只掛 `rpg/`,每次動 `sw.js` 都要請開發者手動補——那是漏登記的主因。

## 三個版號,各自獨立,不要混

| 版號 | 位置 | 什麼時候 +1 |
|---|---|---|
| `RPG_VER` | `rpg/index.html` | 改任何 `.js` / `.css` |
| `IMG_VER` | `rpg/index.html` | **只有真的換圖時** |
| `CACHE`(`arcade-vNN`) | 根目錄 `sw.js` | 要讓已安裝 App 的舊使用者立刻拿到資源時 |

`sw.js` 策略是 **network-first**,**不要改成 cache-first**——`rpg/index.html` 沒有版號,
cache-first 會永遠餵舊的 index.html → 舊的 `RPG_VER` → 整個版本機制失效。

**部署**:桌面資料夾不是 git repo,手動上傳到 `im-chair/im-chair.github.io`。
上傳範圍＝ **`rpg/` 整包 + 根目錄 `sw.js`**。曾漏傳 `sw.js`,導致有網路時正常、離線缺圖。

**新增圖片是三件事,缺一不可**:

1. 放檔(檔名＝資料表的 key/slug)
2. 資料掛勾(`data.js` 該筆加 `img:1` / 加進 `ITEM_ICON` / 加進 `EV_IMG`)
3. `sw.js` 的 `RPG_MON`/`RPG_UI`/`RPG_EQ` 補一筆 ＋ `CACHE` +1 ＋ `IMG_VER` +1

> 只換內容、檔名不變時,第 3 項仍然要做,否則破不了快取。

**做完一定跑 `node rpg/_audit_assets.js` 驗第 3 件。** 它把三邊對起來:
遊戲實際會請求的圖 ／ `sw.js` 登記的 ／ 硬碟上真的有的檔。
漏登記的話線上**完全正常**,只有離線才缺圖——這是最難靠手測發現的一類,不要用眼睛驗。

> 唯一推導不到的是 `data.js` 的 `RUNTIME_MON_IMG`——那幾隻在 `run.js` 用 `e.imgKey`
> 借別人的檔名(寶箱怪、詐屍),`key` 要留給圖鑑統計。新增這類借用圖時要回去補那份常數,
> 否則 `preloadArt` 與對帳腳本都看不到它。

## 規則一:開發備註絕不進入玩家看得到的文字

**玩家可見欄位**＝ `SKILLS`/`AFFIXES`/`ITEMS`/`POTIONS` 的 `n`、`d`,`CLASSES` 的 `desc`,
`REALMS` 的說明,以及所有 `toast()`、`openSheet()`、`showEventScreen()`、`showSkillUpScreen()` 的字串。

這些欄位只寫「玩家在遊戲中需要知道的功能」,用功能性寫法:

- ✅ `d:'重擊並附加易傷'`
- ✅ `d:'獲得格擋(生命×0.05＋體力×0.5)'`
- ✅ `desc:'高物攻、高防禦。站著換血,把仗打成自己的節奏。'`(世界觀語氣僅限 `CLASSES.desc`)

**絕不出現**:版本號、常數名、函式名、行號、平衡理由、待辦、TODO、
「暫時」「之後要改」「待確認」、數值出處說明、任何寫給開發者看的話。

- ❌ `d:'重擊並附加易傷(v419 由 ×1.8 上調,待觀察)'`
- ❌ `toast('碎銀不夠 — 見 boxPrice()')`

開發備註一律寫成程式碼註解,放在被改的那一行上方,寫「為什麼」而非「改了什麼」。
需要交代決策脈絡的寫進 `設計筆記.md` 或 `更新日誌.md`,不要塞進資料欄位。
**不確定某段文字玩家會不會看到,先問,不要猜。**

> 註:`data.js` 的敵人 emoji(`i:'🐀'`)與 `EV_IMG` 的 emoji key 是刻意留著的
> 查表/回落機制,不是漏改,不要動。

## 規則二:同一個數值只能有一個來源

最常吃虧的 bug 是:改了碎銀價格 / 認證樓層 / 鑽石數量,卻只改到其中一處。

v420 的鑽石不同步就是這樣來的——而且當時只「新增了正確的路」,
錯的那條留在旁邊沒拿掉,一路活到 v423 才清乾淨。
**收斂時務必把舊寫法刪掉,不是加一條新的就算數。**

任何時候要讀或算下列東西,一律呼叫既有入口,**不准就地重寫或寫死數字**:

| 對象 | 唯一入口 |
|---|---|
| 貨幣顯示 | `syncWallet()` ＋ `core.js` 的 `WALLET` 表(新增顯示點＝往 `WALLET` 加一筆) |
| 存檔/同步 | `save()`(會順帶 `syncWallet`) |
| 認證深度 | `certDepthOf(cyc)` / `certPool()` / `cd(n).cp` |
| 輪迴解鎖 | `cyclesUnlocked()` |
| 符文里程碑 | `runeMaxRar(cycle, floor)` |
| 符文生成 | `makeRune(floor, cyc)`(黑市補貨走同一支,不是另一條路) |
| 符文售價/購價 | `runeSellVal()` / `runeGemPrice()` |
| 裝備箱價格 | `boxPrice()` |
| 黑市刷新費 | `marketRerollCost()` |
| 鐵匠花費 | `reforgeCost()` |
| 毒燃跳傷 | `dotHitEnemy(e,kind,raw)` / `dotCapRate(e)` |
| 祝福授予 | `grantBless()` |
| 存檔欄位遷移 | `migrateChar()` |
| 素質/上限換算 | `STAT_DIV` / `RATE_CAP` / `VAMP_CAP` / `MREGEN_CAP`(`data.js`,勿在別處複製門檻) |
| 圖片 URL | `enemyIcon()` / `uiIcon()` / `itemIcon()`(都吃 `IMG_VER`) |

> `G.rec.cert` 僅供徽章顯示排序,**不得用於任何難度判定**——黑市/懸賞/解鎖請用
> `certPool()` 與 `cd(n).cp`。這條 v381 犯過一次(本源通關只刷到 31–41 層的貨)。

**工作方式**

1. 動任何數值前,先 grep 全專案找出所有讀寫點,把清單列出來,再開始改
2. 發現同一數值散落多處時,先提議收斂成單一函式或常數,不要跟著再複製一份
3. 新增讀取點時優先擴充既有入口,不要新寫一段
4. 收斂完成後,回頭 grep 確認舊寫法真的沒有殘留

## 規則三:改版號就要同步寫更新日誌

更新日誌:`rpg/更新日誌.md`,新的加在「版本紀錄」最上面。開工前先讀它的「使用說明」段。

只要 `RPG_VER` 或 `IMG_VER` 有變動,**就必須在同一次修改裡補上日誌區塊**。
改版號與寫日誌是同一個動作,不准分兩次做,也不准說「之後再補」。
若改了 js/css 卻沒動版號,先提醒開發者版號要 +1。

每筆日誌的格式:

```
## vNNN — 一句話主題
`CACHE=arcade-vNN`(未變動也要註明未變動)

- 改了什麼、為什麼改(只寫改了什麼等於沒寫)
- 觸及的函式／常數／DOM id 全部列出
- 刻意「沒做」或「評估後不做」的,也要寫,並附理由
```

日誌是給開發者看的,可以寫常數名、行號、待辦——
但這些內容**一律不得複製進玩家看得到的文字**(規則一)。

> 純文件改動(只動 `.md`)不進版號,也不需要日誌區塊。

## 規則四:工作紀律(都是實際踩過的坑)

1. **不要估數值,量出來。** 憑印象猜門檻(灰條亮度、去背容差、陰影飽和度)三次全錯。
2. **驗證一定要從 source of truth 讀回來再驗。** 用試算值畫的驗證圖看起來有驗,驗的是別的東西。
3. **改檔一律先完整讀進變數,全部改完才寫回。**
   `open(f,'w').write(open(f).read()...)` 會先截斷檔案 → 曾把 `style.css` 清成 0 bytes。
4. **用正則改資料表,先數清楚命中數,改完 grep 回查。**
5. **刪程式前先確認它是不是條件鏈的一環**(刪掉 `if` 會讓 `else if` 變孤兒)。
   改完跑 `node --check`,動到 core/run/battle/ui 再跑 `node _smoke.js`;
   動到圖片或 `sw.js` 跑 `node rpg/_audit_assets.js`。
6. **新增「可能是 HTML」的參數時,回頭檢查所有消費端**有沒有還在用 `textContent`。
7. **處理素材前先確認它是哪一類**(切格殘渣要過濾,乾淨 sprite 只要 bbox 裁切),
   並確認是不是已經處理過(檔名帶 `fixed` ＝已處理)。
8. **批次處理的結果一定要畫成對照圖看過**,光看檔名不會發現搞反了。

## 魔符系統開工前已經鋪好的接點(v438–v442)

程式碼裡已經有幾個為魔符預留的位置,實作時是「把佔位換成真東西」,不是從零長出來:

| 位置 | 現況 |
|---|---|
| `core.js` `G.sigils = {equipped:[], owned:[]}` | v424 建好,**目前沒有任何程式讀寫** |
| `data.js` `SIGIL_SLOTS = 2` | 戰鬥畫面技能格固定六格,後兩格是停用的「魔符／未設定」虛線鈕 |
| `battle.js` `renderBattle()` 尾端 | 產生那兩個佔位鈕的迴圈,換成真技能即可,**版面高度不會變** |
| `items.js` `gearTabTo('sigil')` | 倉庫第四個分頁,灰掉、點下去只 `toast('魔符尚未開放')` |
| `items.js` `marketStall` 註解 | 寫了 `2=魔符`,但**黑市沒有那個攤位**,要新做 |

**還沒有的東西,要一起設計:**

- **裝備入口**。符文槽在角色檢視(`ui.js` 的「符文槽 N/3」按鈕),魔符沒有對應的東西
  ——戰鬥畫面雖然留了兩個技能格,但玩家**無處可把魔符裝上去**。
- 魔符本體的資料表、生成、取得管道(掉落?黑市?成就?)。
- 分解/販售價(裝備走 `salvageVal`、符文走 `runeSellVal`,魔符要自己一支或沿用)。

**沿用既有入口,不要另寫:**
`itemRowHtml()`(清單列)、`affixTone()`(詞綴分色)、`gearVisible()`(目前可見清單)、
`salvageVal()`／`runeSellVal()`(售價)、`uiIcon()`／`itemIcon()`(圖片 URL,吃 `IMG_VER`)。
