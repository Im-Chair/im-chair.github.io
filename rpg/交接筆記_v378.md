### 1. 輪迴裝備縮放(cycK 制,v367)

**問題**:舊制 `×(1+CYC_VAL)` 整值乘,把詞綴的「骰值常數」一起放大 → 詞綴 8 層就爆高、基礎值 34+ 層才跟上,兩者脫鉤。體感是「本源畢業裝直推輪迴 I 100,掉落沒有換的理由」。

**改法**:`CYC_K = [1.5, 4.3, 12.3]`(≈0.79×CYC_MULT)**只乘樓層項**:
- 基礎值 = `6 + 0.6·f·K`(等效樓層 `f×K` 進 CURVE)
- 素質詞綴 = `骰值 + 0.3·f·K`(骰值常數不吃輪迴)
- hp/mp 詞綴無樓層項,維持整值 ×K
- 祝福縮放拆成獨立的 `BLESS_CYC`(凍結舊值),與裝備管線脫鉤

**結果**:每重輪迴換裝交叉點自動落在 36–44 層(I:44 / II:39 / III:36),詞綴交叉 33 層與基礎值同步。

### 2. A 閥:毒燃首領承傷閥(v368)

玩家施加的毒/燃,每回合每種上限 = 敵生命上限 × capRate:

| 敵人層級 | 上限 |
|---|---|
| 雜魚(含王隨從) | 無上限 |
| 精英(域限/一般)、小王 | 8% |
| 域主、最終王 | 5% |

- 唯一入口 `dotHitEnemy(e,kind,raw)` + `dotCapRate(e)`(battle.js),三個跳傷點全部導過去
- 額度掛 `e._dotUsed`,`startPlayerTurn` 重置
- **閥吃加成**(A 案):`cap = 敵生命×rate×dotAmp(kind)`,劇毒/烈焰/蝕魂同步抬高上限,不會變死詞條
- 層數照疊(餵絞殺/腐燃、延長受頂回合),只封跳傷
- UI:超閥層數灰字、tooltip 說明
- **催毒豁免**:催毒的立即跳傷不計入額度(否則對王邊際為 0)

### 3. B 閥撤回(v369)

原規格「每回合吸取回復 ≤ 15%(盜賊20%)生命上限」**實作後撤回**。

**撤回理由**:以生命上限為基準,而生命上限正是高輪迴唯一不吃 cycMult 的數值。實測(輪迴I 100層:血量 300、每回合承傷 ≈314、雜魚戰需 5 回合)下額度僅 45/回合 = 直接刪除盜賊。且吸血已有 `VAMP_CAP` 一道上限,兩道閥必有一個是裝飾品。

**病灶(尚未解決)**:高輪迴的過剩續航,根因是「血量/護甲/格擋不吃 cycMult,只有率與按比例回血能跟上」→ 吸血成為唯一活路,砍不得。真正該做的是讓血量或減傷有一條吃輪迴的成長軸。(v377 的壁壘吃血量、屏障吃魔力已往這個方向走了一步。)

### 6. 假稀有度 bug(v374–375)

**症狀**:撿到「稀有品質但 0 詞綴」的裝備。

**根因**:四處 code 用「先生成、再硬改 `it.rar`」,但詞綴是照原稀有度骰的。稀有度分佈改成「首領也常掉白裝」後,force-bump 幾乎每次觸發。

**修法**:`makeItem(floor, bonus, cyc, forceRar)` — 在骰詞綴**之前**定稀有度。四處全改(首領主掉落直接移除 force、最終王/黑市/密室/懸賞獎勵改用 forceRar)。全域已無任何 `.rar =` 硬改。

### 7. 技能全面改版(v377、v378)

**公式改加法**(關鍵):`poisonAmp`/`debuffAmp` 由 `mult×(1+amp×n)` 改 **`mult + amp×n`**(battle.js 共 5 處)。原乘法會讓絞殺 20 層 = ×10.5;加法制下全大招條件全開收斂到 **×5.5**。

**數值**:見下方「技能總表」。

**魔力改 %制**:`manaPct`(最大魔力的%)取代固定 `mana`。解決「前期吃緊、後期垃圾」。

**魔力轉戰力**(`MANA_DMG_K = 0.5`):法術傷害加入「消耗魔力×0.5」項 → 池30花3 與 池1000花100 不再同傷害。實測魔力項佔攻擊輸入 13–18%,跨階段穩定。

**全職業統一法力池**(原本物攻職只有裝備 mp)= 魔符系統的前提。回魔改 `25 + 精神/10 + mregen`。

**其他**:`GARROTE_AMP_CAP` 5→20;`execMult` 取代寫死的 ×1.5;災厄移除單體強化模式與自帶鋪滿負面(附負面只有精進「輪迴咒」才有,各 1 層);輕靈改附易傷(與蝕擊的虛弱區隔)。

## 二、關鍵公式速查

```
傷害 = (武器攻擊×合手 + 主素質 + 消耗魔力×0.5) × 武器係數 × 招式倍率
        └ 「消耗魔力×0.5」只有法術招式吃(MANA_DMG_K)

最大魔力 = (30 + 精神×2 + 裝備mp) × 符文mp乘率      ← 全職業統一
回魔/回合 = 最大魔力 × (25 + 精神/10 + 回法詞綴)%   ← 上限 100%
魔力消耗 = 最大魔力 × manaPct% × manaMul

最大生命 = (50 + 體力×2 + 生命詞綴) × 符文hp乘率
格擋(壁壘) = 最大生命×0.05 + 體力×0.5    (厚壁0.9 / 尖壁0.3)
護盾(屏障) = 最大魔力×0.2 + 智力×1.2     (堅壁1.8 / 反射膜1.0)

裝備基礎值 = (6 + 0.6 × 樓層 × cycK) × 稀有度倍率(區間roll) + 精煉加成
素質詞綴   = 骰值 + 0.3 × 樓層 × cycK
等效樓層   = 樓層 × cycK       ← 跨輪迴比較裝備強度的唯一正確基準

cycK  = [1.5, 4.3, 12.3]  (無限段 ×2.3/重)
cycMult(敵人) = [1.9, 5.5, 15.7]  (無限段 ×2.86/重)

承傷 = ((敵傷 − 防禦力/10) × (1 − 防禦率%)) → 格擋 → 護盾
毒/燃 = 目標最大生命 × (前10層各1.5%,尾段 毒0.5%/燃1%),每回合層數減半
```

**等效樓層對照表**(跨輪迴比較用):

| | 10層 | 25層 | 50層 | 75層 | 100層 |
|---|---|---|---|---|---|
| 輪迴I | 15 | 38 | 75 | 113 | 150 |
| 輪迴II | 43 | 108 | 215 | 323 | 430 |

## 四、黑市/懸賞/新武器 ✅ v380 已全部施工

> 以下 A、B、四之二三項在 v380 全部進 code 並驗證過。實作與原規格的差異都標在各節。

### A. 黑市/懸賞的輪迴切換 bug ✅ 已修

**症狀**:開啟新輪迴後,黑市只賣得到新輪迴低層的垃圾裝,懸賞也接不到舊輪迴高層任務。

**根因**:`certScore = 輪迴×1000 + 樓層`,全遊戲只存**一筆**「最強認證」`G.rec.cert`。踏進輪迴III 逃脫第1層(3001)就蓋掉輪迴II 100(2100)。黑市(`certGearCtx`)與懸賞(`genBounty`)都讀這一筆。

**量級**:黑市武器 base 從 238 掉到 12(−95%)。

**正確基準**:等效樓層 `floor × cycK(cycle)`。輪迴II 70(301)確實勝過輪迴III 20(246)。

**好消息**:每個輪迴的認證樓層**已經分開存了**(`G.cycData[c].cp`、`G.orig.cp`),不用動存檔結構。

**採用:完整方案(分開記每個輪迴)+ 黑市商品分頁**。使用者已拍板,規格如下。

#### A-1 認證改成「每個輪迴各記一筆」

- `G.rec.cert` **降級為純展示用的最高成就徽章**(營地那行字),黑市與懸賞一律不再讀它。
- 新增 `certPool()`:掃 `G.orig.cp` 與 `G.cycData[c].cp`,回傳所有 `cp>0` 的 `(輪迴, 樓層, 等效樓層=floor×cycK)`,依等效樓層排序。**存檔結構不用動**,資料本來就分開存了。
- `cyclesUnlocked()` 改讀 `cd(n).cp >= CYC_NEXT`,不再依賴 `certScore` 的 `cycle*1000+floor` 編碼。下潛選單的解鎖提示同步改。
- `certScore()` 只留給徽章排序用。**不刪**,但要在函式上方註明「僅供展示,勿再用於難度判定」。

#### A-2 黑市:每個已認證輪迴一個分頁

- 分頁 = 已認證的輪迴,依**等效樓層由高到低**排序(本源 / 輪迴I / 輪迴II / 輪迴III / 無限)。預設停在等效樓層最高的那一頁。
- **自動隱藏過期分頁**:等效樓層低於「最高分頁的 40%」的頁不顯示,避免累積出三頁沒人看的垃圾。本源在開輪迴II 之後就會自然消失。
- 每頁貨源獨立:樓層取該輪迴的 `[cp−10, cp]`,輪迴用該頁的輪迴。每頁 **2–3 件**(原本 2–4 件是整個黑市的量,分頁後要縮,否則貨量爆炸)。
- **符文攤跟著分頁走**:`runeMaxRar(該頁輪迴, 該頁樓層)` 自然 gate,低階分頁就是沒符文賣,不用另外寫規則。
- **材料攤只掛在最高分頁**(材料不分輪迴,重複出現沒意義)。
- 整個黑市仍以 `G.rec.runs` 為 key 每趟重骰一次,所有分頁一起換貨。

> ⚠️ 設計上的誠實話:分頁不是「有取捨的選擇」,而是**一道價格階梯**。高分頁的裝備就是比較強也比較貴,錢夠就買高的。分頁真正的價值在於「你剛踏進輪迴III,還是買得到符合你實際實力的輪迴II 貨」——也就是修掉這個 bug 本身。不要事後又幫分頁加什麼「低分頁限定好處」去硬造抉擇,那是為機制找工作。

#### A-3 懸賞板:4 格不變,配額跨輪迴

- 維持 4 格,難度帶配額改為:**最強輪迴 3 格(挑戰1 / 評定2)+ 其他已認證輪迴隨機抽一個,出 1 格「該輪迴 cp 以下」的可刷任務**。
- 只有一個已認證輪迴時,退回現行的 above/at/at/below。
- 委託本來就帶 `b.mode`(輪迴),跨輪迴任務**要回去那個輪迴下潛才能完成**——這是特性不是 bug,給舊輪迴一個回訪理由。
- 獎勵已經吃 `cycMult(mode)`,舊輪迴任務自然給得少,不用另外壓。

實作:`boxPrice = (80 + 等效樓層×8) × 1.35^稀有度`,等效樓層 = `it.pf × cycK(it.pc)`。

- 係數對齊舊制:本源 50 層的白裝仍是 480🪙,前期無感。

| 輪迴II 100 | 430 | 3,520 | 8,661 | 1,530 / 4,860 |
| 輪迴III 100 | 1,230 | 9,920 | 24,407 | 2,295 / 7,290 |

> ⚠️ **踩過的坑,記下來免得再犯**:我第一版把價格曲線刻意壓平,理由是「單場戰鬥的碎銀收入每輪迴只成長 1.6 倍,而裝備強度成長 cycK≈2.9 倍/重,價格跟著強度走會買不起」。
> **這個理由是錯的。** 碎銀是**累積的存量**,裝備強度是**當下的值**,兩者不在同一條軸上,不能比成長率。
> 「多刷幾趟累積碎銀去買貴裝備」本來就是設計意圖——價格就是要跟著強度走。
> 舊制 `×1.5^輪迴` 只成長 3.4 倍,而裝備強度成長 12.3 倍,等於高輪迴裝備在打折,那才是要修的地方。

### B. 黑市稀有度 ✅ 已改:四種都賣、偏高階

**原問題**:黑市寫死 `mk(Math.random()<0.35?3:2)`,只賣稀有和傳說。但稀有度倍率已反轉(**白裝基礎值最高、橙裝靠詞綴數**),等於黑市只賣基礎值最低的貨,玩家在深淵撿的主力白/藍反而買不到。

**改法**:

1. **比例**:以該分頁樓層的自然掉落分佈(`rollRarity`)為底,**整體往上推約一階**——橙的機率約為野外的兩倍、白降到野外的一半。四種稀有度都上架,但體感是「好貨集散地」。不要照抄野外分佈,否則黑市只是付費掉落、失去存在理由。
2. **定價改四檔,而且要反映稀有度反轉**。現行 `橙 480+deep×6 / 其餘 140+deep×2`(約 3.4 倍落差)是舊哲學的遺留——反轉後白裝基礎值最高,不該賣得像垃圾。
   - **價格主體改看等效樓層**(等效樓層決定基礎值,也就是這件裝備的實際強度)。
   - **稀有度只加溢價,不當主導**:每高一階約 +35%(白→橙約 2.5 倍),取代現在的 3.4 倍斷崖。
   - 這樣「高 roll 的白裝」售價會逼近低 roll 的金裝,和 v372 的設計意圖一致。
3. **盲盒/明盒機制保留**:`type:'open'`(看得到內容、貴 30%)vs `type:'box'` 是黑市真正的賣點,不動。

**實作**:直接沿用既有的 `rollRarity(floor, bonus, cyc)`,黑市傳 `bonus=2`(首領權重 白×0.5 橙×2)——**不用寫新的分佈函式**。順帶給 `rollRarity` 加了第三參數 `cyc`,因為營地 `R=null` 會被當 cycle 0(和當初 `makeItem` 踩過的是同一個坑)。

實測(輪迴II 100 分頁):黑市 白26% 藍17% 金25% 橙32%,野外同層 白52% 藍13% 金19% 橙15%。白減半、橙加倍,如規格。

## 四之二、新增兩把法系武器 ✅ v380 已實作

**背景**:物攻三把(匕首/劍/斧)的差異全在同一條軸上——行動點 × 係數,三把乘積都是 3.0–3.2,個性來自 `blockMod` 穿盾與一個小特權。法系只有杖,而且杖也長在同一條軸上(3×1.0),**完全沒用到法系獨有的第二條資源軸:魔力**。

新增的兩把都要長在魔力軸上。

### 魔典(書)——法系的匕首位

| 欄位 | 值 |
|---|---|
| pts | 4 |
| coef | 0.8 |
| blockMod | **1.2**(對格擋最差) |
| magic | true |
| 特殊 | 法術魔力成本 **−25%** |

- 每回合權重 4×0.8 = **3.2**,與匕首同級(全武器最高),所以**必須付匕首同樣的代價:blockMod 1.2**。這是刻意對稱,不要偷偷改回 0.5。
- ⚠️ **不要用 `MANA_DMG_K` 當平衡理由**。成本降 25% 只讓「消耗魔力×0.5」那一項降 25%,而該項僅佔攻擊輸入 13–18% → 實際傷害只掉約 4%。真正的平衡來自 `coef 0.8` 與 `blockMod 1.2`,`MANA_DMG_K` 幾乎不參與。
- **啟用方式:被動,不需要 UI**。技能格本來就顯示魔力成本,換上魔典後數字直接變小,玩家看得見(符合「看不見的機制等於不存在」)。
- 定位:疊 debuff / 多段 / 連放輔助的制魔師。天然張力=回魔每回合只有池子的 25%+,4 點連放會第一回合爽、第二回合乾。

### 咒鈴(靈擺)——魔力換行動點

| 欄位 | 值 |
|---|---|
| pts | 3 |
| coef | 1.0 |
| blockMod | 0.5 |
| magic | true |
| 特殊 | 每回合限一次:花 **40% 最大魔力** 換 **1 行動點** |

- 這把是全遊戲唯一把「行動點」與「魔力」接起來的東西,創造物攻武器做不到的決策:**這回合多一個動作,還是留魔力給大招?**
- **成本必須 > 回魔率,否則是永久 +1 行動點的 exploit**。基礎回魔是每回合最大魔力的 25%,所以**成本設 40%**(不是原構想的 25%)。設 25% 時,一個只放物理普攻(敲擊/杖擊,不耗魔)的法師會被回魔完全補上,等於白拿永久第 4 點。
  - 註:`mregen` 詞綴堆滿可以把回魔推到 100% 上限,屆時確實撐得住每回合開。**這視為合法的 build 報酬**(用詞綴欄位換行動點),但列入觀察。
- **啟用方式:行動點顯示旁一顆常駐小按鈕**(`p-energy` 所在的 `pz-top`)。顯示「◆+1 / 🔵40%」,魔力不足或本回合已用過就灰掉。**不做自動觸發**——自己選擇超支才是貪婪主題。
- 與**蓄招**的互動:現行規則是點數不足時點技能會起蓄(花光點數、下回合放)。拿咒鈴時這變成一個真的分岔——**免費但慢的蓄招 vs 花魔力立刻放**。這是白賺的決策深度,不用額外寫規則。

### ⚠️ 連帶必須改的:武器類型抽選要偏權(`pickWeaponType`)

加兩把魔攻武器會讓 `pick(['dagger','sword','axe','staff'])` 從 1/4 魔攻變成 3/6,**物攻職一半的武器掉落直接變垃圾**(`weaponFit` 對物攻職拿魔攻武器回 0)。

改成**該職業用得到的那組佔 75%、另一組 25%**:

| | 舊制(4選1均分) | 新制 |
|---|---|---|
| 劍士/盜賊 | 25% 掉到杖(全廢) | 26% 魔攻 — **持平,沒有變差** |
| 法師/制魔師 | 75% 掉到物攻武器(法術傷害歸零、普攻只剩 50%) | 25% — **大幅改善** |

換句話說,受害最深的本來就是施法職,這次順手一起修掉。留 25% 給另一組,維持「其他武器存在」的質感與變賣價值。

### 共同注意

- `weaponFit` 讓物攻職拿魔攻武器 = 0,所以這兩把只服務法師/制魔師。
- `WEAPON_NAMES` 已補兩組名稱池;`itemStatLine` 的 perk 標籤補了「省魔」「換點」。

## 六、審查/施工紀律(踩過的坑)

1. **加法 vs 乘法**:`每層+10%` 在本作是**加法**(`mult + 0.1×n`),不是乘法(`mult × (1+0.1×n)`)。看到「+X%」先確認是哪一種——差別是絞殺 5.5 還是 10.5。
2. **不要估數值,跑 code 算**。本輪多次因為憑印象估面板(「900血/960輸出」)而給錯結論;實際是輪迴I 100 約 300血/500攻。要數字就 `node` 載入 data.js 實算。
3. **閥值只能寫在單一入口**,散寫等於製造下一個 `scaleMult` 死程式。
4. **「先生成再硬改」是禁忌**——改稀有度/屬性一定要在生成前決定(見 forceRar)。
5. **改分佈會引爆別處的潛在 bug**:稀有度分佈一改,沉睡的 force-bump 立刻爆出假稀有度。改機率類參數後要回頭掃相關 code。
6. **對抗成長型數值的機制自己也要有成長曲線**——B 閥就是踩這條翻車的(綁生命上限,而生命上限不吃 cycMult)。
7. **玩家看不見的機制等於不存在**——加閥必配 UI(灰字層數、額度顯示)。

### 分頁隱藏門檻

`certPool()` 過濾掉等效樓層 < 最強者 **25%** 的分頁。最初寫 40%,實測在最常見的情境(輪迴II-100 + 輪迴I-100)會把輪迴I 濾掉,導致分頁只剩一頁、功能等於隱形。低分頁的價值是「便宜」,錢不夠時仍是真選項,所以放寬到 25%。

### v381 修正:`cp`(傳送點)≠ 認證深度

**症狀**:打穿本源 50 層,黑市卻只刷得到 31–41 層的裝備。

**成因**:`certPool()` 第一版拿 `cp` 當認證深度,但 **`certifyDepth` 把本源的 `cp` 刻意封在 41**(不讓玩家傳送到 50 層直接跳過首領)。輪迴 1+ 的 `cp` 無上限,所以兩者碰巧相等——**只有本源會露餡**,而本源正是每個新玩家的第一段。

**修法**:新增 `certDepthOf(cyc)` = `max(deep, cp)`。`deep` 與 `cp` 同樣只在 `bankRun`(逃脫/通關)推進,規則一致;取 max 只是為了相容任何 `cp>deep` 的舊檔。`certPool()` 與 `cyclesUnlocked()` 都改走這個唯一入口。

> 教訓:**`cp` 是「解鎖了哪個傳送點」,不是「認證到多深」**——它有本源封 41 這個業務規則在裡面。要「認證深度」請一律用 `certDepthOf()`,不要再直接讀 `cp`。
> 這也是「同一份資料被兩種語意共用」的典型:`certifyDepth` 一次做兩件事(認證＋解鎖傳送),兩者的封頂規則卻不同。

## 十一、v384:實機回報的三個 bug

### 1. 護甲/飾品完全沒套到圖(顯示 emoji 回落)

**成因**:`makeItem` 最後會補前綴——`it.name = pick(PREFIX[rar.id]) + it.name`(傳說還可能再加「詛咒的」)。所以實際名字是「王殞鱗甲」「精良的油燈」,拿整串去查 `ITEM_ICON['鱗甲']` 當然查不到。

**武器沒踩到,是因為它查的是 `it.wtype` 不是名字**——這剛好掩蓋了問題,兩條路徑不一致才會只壞一半。

**修法**:`itemIconSlug` 改比對**字尾**(`name.endsWith(key)`)。已對 12 前綴 × 12 名稱 × 有無詛咒 = **312 種組合全數驗證通過**。

> 教訓:**顯示名(`name`)是會被裝飾的,不能當 key 用。** 未來若要用名字查任何表,一律走字尾比對,或在生成時另存一個乾淨的 key 欄位。

### 2. 裝備圖偏下且被裁切

**成因**:第一版切圖用固定百分比(垂直 8%–78%)去避開底部的中文標籤,但**素材的畫面重心是對齊整格中心的**,所以那個視窗的中心落在 43%,主體被推到偏下、底部超出的部分被切掉。

**修法**:改成**逐格偵測主體 bbox**(亮度高於該格暗底的區域),再以 bbox 中心取正方形、外擴 14% 留白。不再用寫死的百分比。

### 3. 雙怪選取同時出現黃方框與黃圓框

`.e-wrap.duo .e-block.sel` 本來就有金色外框(style.css:177),v382 為了點陣圖又加了一圈 `::before` 光圈——**兩個記號疊在一起只是噪音**。已移除光圈,外框留著。SVG 的染金保留(不影響)。

> 當初加光圈的理由是「點陣圖吃不到 `currentColor`」,但沒先確認**既有的外框已經解決了同一件事**。加新回饋前要先看現有的夠不夠。

## 十六、v389:修 v388 的致命 bug + 加冒煙測試

### 症狀

選完角色/職業後**卡在選職業畫面,進不了營地**。

### 成因

```js
(window.requestIdleCallback || (f=>setTimeout(f,300)))(batch);   // ← v388 的寫法
```

把 `requestIdleCallback` 從 `window` 取出來**再直接呼叫**,`this` 就不是 `window` → 瀏覽器丟 **`TypeError: Illegal invocation`**。

這行在 `preloadArt()` 裡,而 `preloadArt()` 被放在 `renderCamp()` 的**第一行**。`confirmClass()` 的流程是:

```js
save(); renderCamp(); showScreen('s-camp');
```

`renderCamp()` 一丟例外,後面的 `showScreen('s-camp')` 就永遠跑不到 → 卡在原畫面。

### 修法(三層)

1. **綁定正確**:`if(typeof window.requestIdleCallback === 'function') window.requestIdleCallback(batch); else setTimeout(batch, 300);`
2. **整個 `preloadArt` 包 try/catch**——它只是最佳化,**絕對不能因為它壞掉就擋住遊戲流程**。
3. **移到 `renderCamp` 最後一行**,不放在任何必要流程前面。

> 教訓:**非必要的最佳化不可以站在必要流程前面,而且要自己包 try。** 這條比「記得綁 this」通用得多——下次加任何背景工作(預載、統計、上報)都適用。

### 新增 `_smoke.js`:無瀏覽器的流程冒煙測試

```bash
cd rpg && node _smoke.js
```

自己刻的輕量 DOM stub(jsdom 在此環境裝不起來),跑完整流程並檢查**最後停在哪個畫面**:

- 新玩家:`load → titleStart → newChar → renderClassSelect → confirmClass` → **必須停在 `s-camp`**
- 切換角色:`openRoster → selectChar(0)`
- 下潛:`openDivePicker → startRun → showDoors → enterDoor → renderBattle`

**關鍵設計:stub 的 `requestIdleCallback` 會在 `this !== window` 時丟 `Illegal invocation`**,跟真瀏覽器一致——所以這個 harness **真的抓得到 v388 那個 bug**(已反向驗證過)。純 `node --check` 只驗語法,永遠抓不到這種執行期錯誤。

**改動 UI 流程後請跑一次 `node _smoke.js`。** 它不能取代實機測試(版面、CSS、觸控都驗不到),但「整個流程炸掉」這類問題會當場現形。
