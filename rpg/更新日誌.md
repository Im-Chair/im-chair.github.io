## 使用說明

### 兩個版號,用途不同,不要合併

兩者都在 `rpg/index.html` 的 `<head>`:

| 常數 | 什麼時候 +1 | 影響 |
|---|---|---|
| `RPG_VER` | 改任何 `.js` / `.css` | 自動套到 CSS 連結、所有 `<script src>` 的 `?v=`、標題畫面顯示的 `V4.NN` |
| `IMG_VER` | **只有真的換圖時** | 所有 `mon/` `ui/` `eq/` 圖片與 `camp3.webp`、`title_bg.webp` 的 `?v=` |

**為什麼拆開**:圖片有 121 張、共 3.0 MB。v393 到 v420 這 27 次進版,圖片一直跟著 `RPG_VER` 變 URL——瀏覽器整批重抓、Service Worker 快取每版累積一整套重複 entry,而圖根本沒動。v421 拆開之後這個浪費停止。

### 站台層級的快取

根目錄 `sw.js` 的 `CACHE`(`arcade-vNN`)是**獨立的第三個版號**,跟上面兩個無關。需要讓「已安裝 App 的舊使用者」立刻拿到資源時 +1,舊快取會在 activate 時清除。

策略是 **network-first**(先打網路、失敗才回快取)。**不要改成 cache-first**——`/rpg/index.html` 沒有版號,cache-first 會永遠餵舊的 index.html → 舊的 `RPG_VER` → 整個版本機制失效。

### 新增圖片是三件事,缺一不可

1. **放檔** — `mon/<key>.webp` / `ui/<slug>.webp` / `eq/<slug>.webp`,**檔名就是資料表的 key/slug**
2. **資料掛勾** — 怪物在 `data.js` 該筆加 `img:1`;裝備加進 `ITEM_ICON`;事件加進 `EV_IMG`
3. **快取進版** — 根目錄 `sw.js` 的 `RPG_MON`/`RPG_UI`/`RPG_EQ` 補一筆 + `CACHE` +1,並把 `IMG_VER` +1

> 只換內容、檔名不變時,第 1、2 項看起來免做——**第 3 項還是要做**,否則破不了快取。

### 部署

桌面資料夾**不是 git repo**,手動上傳到 `im-chair/im-chair.github.io`。上傳範圍是 **`rpg/` 整包 + 根目錄 `sw.js`**。曾經漏傳根目錄的 `sw.js`,結果線上 `rpg/` 是新的、`sw.js` 停在兩週前——有網路時看不出來,離線就缺圖。

## v424 — 存檔欄位一次加完(四個新系統的地基)
`CACHE=arcade-v41`(未變動)

施工順序第 1 項。四個新系統(素質提升／魔符／成就／離線化)的欄位必須先落地,
其餘三個系統才有地方寫資料;若先做魔符再回頭補存檔,舊存檔會被遷移兩次。

**新增的五組欄位**(`core.js` 的 `newSave()` 與 `account.js` 的 `migrateChar()` 同步加)

| 欄位 | 結構 | 用途 |
|---|---|---|
| `c.statBuy` | `{str,int,spi,vit,agi:0}` | 素質提升:各素質已購點數(0～40) |
| `c.runeSeen` | `{ affixKey: 歷史最高值 }` | 成就:符文集齊判定 |

| `c.sigils` | `{equipped:[], owned:[]}` | 魔符:已裝備欄位與已擁有清單 |
| `c.killBest` | `0` | 單場殺怪數的歷史最高 |

`statBuy` 的補值是逐 key 檢查而非整包判斷——半殘的存檔(只有 `str`)也補得回來。
`sigils` 的兩個陣列同理。

**`seenRune(rn, c)` — 符文曾取得的唯一登記入口**

`c.runeSeen` 記的是**數值**不是稀有度:集齊判定要拿 `RUNE_BAND[cat.band][3][1]` 的傳說上限去比,
只記稀有度判不出來。`c` 省略時寫進 `G`,`migrateChar` 補登舊存檔時要把該角色傳進去
(那時 `G` 還不是它)。

**沒有照規格 1.3 埋在 `makeRune()`,這是刻意的。** `makeRune` 有兩個呼叫點:
`battle.js` 的掉落,以及 `items.js` 的黑市補貨(`rollMarketRunes`)。埋在 `makeRune` 等於
「攤位上出現過就算取得」,花 1 鑽刷新攤位就能集齊,四個符文成就的難度會直接歸零。

改成埋在**真正入帳**的兩處:
- `run.js` 的 `bankRun()`——成功回營才入帳,死亡失去的不算(與「死亡失去未保管的一切」同一套規則)
- `items.js` 的 `buyRune()`——黑市買下

`migrateChar` 另外把現有 `c.runes` 與 `c.runeBag` 補登進 `runeSeen`,否則老角色一啟用就少一截進度。
賣掉或換掉的追不回來,這是舊存檔沒有這個欄位的必然代價。

**驗證**

`node --check` 七檔全過、`_smoke.js` 全過,另寫了 12 項針對性測試全過:
新舊角色欄位一致、半殘 `statBuy` 補值、既有資料不被覆寫、鑲嵌+背包補登取最大值、
`seenRune` 只往上寫、20 個詞綴的門檻都對得上 `RUNE_BAND`、`makeRune` 本身不登記。

## v421 — 圖片版號獨立 + 深淵成為獨立 PWA
`CACHE=arcade-v40`

**`IMG_VER` 拆出來**

七個構造圖片 URL 的地方全改吃 `IMG_VER`:`enemyIcon`、`uiIcon`、`itemIcon`、進域橫幅、`campRatio` 的探測圖、`preloadArt`,以及 `style.css` 的 `camp3` 與 `title_bg`。

順帶釐清一個誤解:`sw.js` 的 fetch fallback 用 `caches.match(req, {ignoreSearch:true})`,**忽略 query string**,所以帶版號的 URL 照樣命中預快取——離線時不受版號影響。真正的代價在成功路徑的 `c.put(e.request, copy)`:存的是帶版號的 URL,每進一版就多累積一整套 entry。那是快取膨脹,不是失效。

**`rpg/manifest.json`**

`start_url:"./"`、`scope:"./"`、standalone、portrait、`#080605`。head 補上 `<link rel="manifest">` 與 `apple-touch-icon`。加到主畫面後是獨立 App,不會再跑到 ARCADE 首頁;iOS 對沒裝到主畫面的網站清快取特別兇,這件事對離線體驗有實質差別。

**`rpg/icon.png`**

原本想從 `title_bg` 裁一張,但 512×512 照片量化到 64 色還 128 KB,對一個預快取資源太浪費——而且 App 圖示不該是縮小的照片。改成手寫 SVG 渲出來的礦坑口(木框 + 紫色深淵 + 兩盞燈 + 收斂軌道),**38 KB**,60px 下剪影仍可讀,內容收在中央 80% 以內所以 maskable 裁圓角不會切到東西。

**評估後不做的兩件**

- **分階段 precache**:SW 的 install 是背景進行,`waitUntil` 只延後 SW 自己 activate,不阻擋頁面渲染。「首開會卡」的前提不成立,收益小。
- **cache-first**:見上面「站台層級的快取」。

## v419 / v420 — 六個回報的 bug
`CACHE=arcade-v39`

**1. 符文的「關閉」鍵沒反應** — 不是按鈕壞掉,是 `openSheet` 沒重設捲動位置。`.sheet` 是 `max-height:78vh` + `overflow-y:auto`;從長表(角色檢視,通常已捲到底)切到短表(符文)時舊的 `scrollTop` 留著 → 看到一片空白、關閉鍵在視窗外。`openSheet` 補上 `el.scrollTop = 0`,**所有 sheet 之間的切換都受益**。

**3. 營地與黑市的鑽石數字不一致** — 根因是**四個地方各自寫一份**:`save()` 寫 `camp-gold`、`renderCamp` 寫 `camp-gem`、`renderMarket` 寫 `mk-gold`/`mk-gem`、`renderGear` 寫 `gear-gold`。回報懸賞後只有一部分被更新。碎銀之前也犯過同一件事。

**4. 刪掉冗贅文案** — 逃脫繩的機率提示整行、兩顆逃脫按鈕的「——活著離開,記錄這趟深度」、商人的繩子說明、舊都規則的「(首領除外)」兩處。

**35 隻雜魚全部來自 `貪婪深淵-怪物素材/mon/`。** 三組同名檔案比對後:`mon/` 那組透明度 0%(背景壓平,貼進遊戲會變色塊),`G0`/`G1` 去背乾淨但只有域 0–1,`R0`–`R4` 涵蓋完整但有切格殘渣。

選 `mon/`(裁切最好)並自己鍵掉背景:從邊緣洪水填充、容差自動從 42 遞增到 120,直到「去背率 ≥55% 且主體還留著 ≥14%」。42 張成功,兩張失敗:

- `crab` — 哥布林本身是綠的,跟墨綠底同色,容差再拉高會把牠吃掉 → 掃 20–90 找到 **55 是唯一切得乾淨又不吃主體**的點
- `hound` `flower` — 底有**徑向漸暈**,二值洪水填充永遠留一塊方框 → 改用**軟鍵**(alpha 依色距連續變化),漸暈段自然淡出;代價是主體最暗處半透明,但這兩隻都在無光通道,「從黑暗裡浮現」正好是那層的美術語言。另加陰影提亮拉齊同域亮度。

**域限精英每域兩隻**(v397 的延續),我在這幾版反覆重做:

- 第一次用「最大連通區塊」過濾,把**身體當成殘渣刪掉**,只留下發光的武器或眼睛。素材本來就是乾淨的透明 sprite,根本不該跑那個流程。
- `acolyte`/`stitch` 的切格灰條前三次沒抓到,因為我**猜**它是亮的(門檻設 >0.40),實際量出來只有 0.21 和 0.36。最後的判準是「中性灰 chroma<10 + bbox 填滿 ≥0.90 + 寬高比 ≥4」——有機的畫不會長成實心矩形。
- 最後換成新素材(白底、身體有明暗),用「每列連通區塊 + 對最寬的那塊在最低密度欄再切一刀」處理橫向相連。

**首領 10 隻改用元素少女**(反差萌,刻意的)。同域小王與域主用同一角色的兩個版本:淺穴冰藍 / 聚落綠 / 無光紫暗 / 舊都金光 / 熔獄火,最終王是火。剩下的藍水與白紫兩角色收進 `mon/_spare/`。

配套:`.e-block` 新增 `boss` class,**首領的中毒/燃燒不吃 `grayscale(1)`**。實測那批的辨識幾乎全靠顏色,全去色後兩兩差異從 51 掉到 25(**辨識度只剩 49%**),而首領戰正是最需要看清狀態的時候。改成壓飽和 + 外圈光暈,原色保留。雜魚維持全去色(它們靠剪影辨識,去色沒差)。
